# 05. Microsoft Intune Endpoint Management

Back to README | Previous: Microsoft Teams | Next: Security and compliance

Intune lets an organisation manage computers and mobile devices without physical access: configure security settings, deploy applications, enforce compliance and run some troubleshooting remotely. I used the Intune admin center for Windows devices and looked at how Intune works with Microsoft Entra ID and Conditional Access.

## 1. How the pieces fit

```mermaid
flowchart LR
    A["Enrol the device"] --> B["Configuration profiles apply settings"]
    B --> C["Compliance policy checks the device"]
    C --> D["Conditional Access uses compliance state"]
    D --> E["Allow or block access to Microsoft 365"]
```

Understanding this order before creating policies avoided trial and error, since each stage depends on the one before it.

## 2. Device enrolment

1. Intune admin center, **Devices, Enrolment, Windows**.
2. Confirm **Automatic MDM enrolment** is enabled for all users.
3. Explore **Windows Autopilot**, which organisations use when deploying new laptops.
4. Create a deployment profile with:
    - User-driven deployment
    - Microsoft Entra ID join
    - **Standard User** account type
    - Automatic setup during the out-of-box experience (OOBE)
    - Enrolment Status Page enabled so users can follow progress

Standard User follows least privilege: local administrator rights would let users install unauthorised software and weaken device security. This documentation records the creation of the profile; registering a device through Autopilot is not recorded.

## 3. Configuration profiles

Profiles apply settings to many devices at once. Both profiles below were assigned to **All Devices**.

**Baseline Security Settings**

- Password minimum length 12 characters, with complexity enforced
- BitLocker encryption required
- Windows Defender Firewall enabled
- Microsoft Defender Antivirus kept running
- Inactive devices lock after five minutes
- USB storage devices blocked

**Browser Settings (Microsoft Edge)**

- Password saving disabled
- Microsoft Defender SmartScreen enabled
- Access to unsafe websites blocked

Blocking USB storage reduces the chance of data being copied off a device without using the company network, which is prevention rather than reaction.

## 4. Compliance policy

Configuration profiles set how devices should be configured. A compliance policy checks that the settings are in place and marks a device **Not compliant** otherwise.

The Windows compliance policy requires:

- BitLocker enabled
- Secure Boot enabled
- Microsoft Defender running
- Firewall enabled
- Antivirus protection enabled
- Windows 10 version 22H2 or later
- Password protection with at least 12 characters

Non-compliance does not restrict access immediately. I set a **three-day grace period**, because a laptop may simply be waiting on updates or a restart. This balances security against disruption.

## 5. Conditional Access

A compliance policy only reports device health. Conditional Access uses that report to decide whether access is allowed.

I created **Require Compliant Device for Microsoft 365 Access**:

- Applies to all users
- Protects Microsoft 365 services including Teams, Exchange Online and SharePoint
- Requires the device to be marked compliant before access is granted

I first put the policy in **Report-only mode** to see what would happen without locking anyone out. Enforcing it later caused the lockout described in Troubleshooting, challenge 1. After that I created two break-glass accounts and excluded them from Conditional Access policies.

## 6. Application deployment

- **Microsoft 365 Apps** (Word, Excel, Outlook, PowerPoint, Teams), assigned as **Required** so they install automatically.
- **Google Chrome**, assigned as **Available**, so users can install it from the Company Portal if they want it.

Business-critical software installs automatically, while optional software is available on request, which keeps devices consistent without clutter.

## 7. Remote device actions

On an enrolled Windows device I reviewed the available actions: Sync, Restart, Remote Lock, Reset Passcode, Wipe, Retire, Fresh Start and Collect Diagnostics. I triggered **Sync** and watched the device check in and apply pending policies.

The difference that matters most:

| Action | Effect | Use |
| --- | --- | --- |
| Wipe | Resets the device and removes everything | Lost or stolen company laptop |
| Retire | Removes company management and business data, leaving personal files | Employee-owned device |


## Summary

I enrolled a device, created configuration and compliance policies, linked compliance to Conditional Access, deployed applications and reviewed remote actions. The device-ownership issue that stopped policies applying is in Troubleshooting, challenge 3.
