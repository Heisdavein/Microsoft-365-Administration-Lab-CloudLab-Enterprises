# 02. Exchange Online

Back to README | Previous: Tenant setup | Next: SharePoint and OneDrive

Email is central to most organisations, and Exchange Online is usually where an investigation starts when someone cannot send mail, needs a shared inbox or reports a suspicious message.

## 1. Users and mailboxes

In Microsoft 365 a mailbox is not created separately. Creating a user and assigning a licence that includes Exchange Online causes Microsoft to provision the mailbox automatically.

1. Microsoft 365 admin center, **Users, Active users**, **Add a user**.
2. Enter name, username, display name and department.
3. Assign a Microsoft 365 E5 licence, which includes Exchange Online.
4. The mailbox is provisioned within a few minutes.
5. Repeat until all 12 users exist across the departments.

I then opened the **Exchange admin center, Recipients, Mailboxes** and reviewed what can be managed per mailbox: permissions, email aliases, forwarding, automatic replies, delegation, mail flow settings, Litigation Hold and storage limits. These are the settings behind many everyday support requests.

## 2. Shared mailbox

A shared mailbox lets several people use one inbox, such as `support@` or `info@`, without sharing a password.

1. Exchange admin center, **Recipients, Shared**, **Add a shared mailbox**.
2. Create `support@cloudlabent.onmicrosoft.com` with display name **CloudLab Support**.
3. Open **Mailbox Delegation**.
4. Grant three IT users **Full Access**.
5. Grant the same users **Send As**.
6. Test: open Outlook as a delegated user, open the shared mailbox and send a message.

The message appeared to come from CloudLab Support, confirming the permissions.

**Why Send As.** With Send As, recipients see only the shared address. With Send on Behalf they see “Name on behalf of CloudLab Support”. A support mailbox should present one consistent identity, so Send As was the better choice.

## 3. Distribution groups

A distribution group delivers a message to every member.

1. Microsoft 365 admin center, **Teams & groups, Active teams & groups**, **Add a group**.
2. Choose **Distribution** as the type.
3. Add the appropriate members.

| Group | Purpose |
| --- | --- |
| `all-staff@cloudlabent.onmicrosoft.com` | Company-wide announcements |
| `finance-team@cloudlabent.onmicrosoft.com` | Finance department |
| `it-team@cloudlabent.onmicrosoft.com` | IT department |
| `management@cloudlabent.onmicrosoft.com` | Managers and department heads |

For `all-staff` I restricted who can send so that only management can email the whole company, which reduces accidental all-company messages. I tested each group by sending a message and confirming every member received it.

## 4. Mail flow rules

Mail flow (transport) rules act on messages as they pass through Exchange Online. I created two.

**Rule 1: external disclaimer.** In **Exchange admin center, Mail flow, Rules**, a new rule applies only to email sent outside the organisation and appends a company disclaimer. A test email to a personal Gmail account showed the disclaimer.

**Rule 2: block dangerous attachments.** A second rule rejects email containing `.exe`, `.bat`, `.ps1` or `.vbs` attachments before it reaches the recipient. A test of this rule is not recorded in my notes, so it is listed as configured.

Blocking risky file types is one layer of defence in depth, working before antivirus inspects the message.

## 5. Spam and phishing protection

Microsoft Defender for Office 365 scans mail for spam, malware and phishing. I reviewed the default anti-spam policy and created a custom policy for all users.

1. Microsoft Defender portal, **Email & collaboration, Policies & rules, Threat policies**.
2. Review the default anti-spam policy.
3. Create a custom policy for all users.

| Setting | Configuration |
| --- | --- |
| Spam | Move to Junk Email |
| High-confidence spam | Quarantine |
| Phishing | Quarantine |
| Bulk email threshold | 6 |
| Safety tips | Enabled |

In the **Anti-phishing policy** I added the CEO and the Finance Manager as protected users, so Defender can detect and warn about attempts to impersonate them from external addresses.

## Summary

Mailboxes follow licences, a shared mailbox gives a team one identity, distribution groups simplify communication, mail flow rules automate handling, and Defender adds anti-spam and anti-phishing protection. Further Defender features are in Security and compliance.
