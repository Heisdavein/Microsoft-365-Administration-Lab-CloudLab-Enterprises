# 04. Microsoft Teams

Teams is where people communicate, meet and work on files, and it depends on SharePoint, Exchange Online and OneDrive. I used the Teams admin center and the Microsoft 365 admin center to configure it as an administrator would.

## 1. Governance: who can create teams

By default almost any user can create a team. In a real organisation that leads to duplicate workspaces, abandoned projects and inconsistent names, so I put basic control in place.

1. Open the Teams admin center (`admin.teams.microsoft.com`), **Teams, Teams policies**.
2. Review the Global (Org-wide default) policy, which allows private and shared channel creation by default.
3. In the Microsoft 365 admin center, review **Groups, Active groups**.
4. Create a security group called `Teams-Creators`.
5. Add only members of the IT and Management departments.
6. In Microsoft Entra ID, configure the tenant so only `Teams-Creators` members can create Microsoft 365 Groups. This also controls who can create teams.

## 2. Teams for each department

In **Teams admin center, Teams, Manage teams**, I created one team per area:

| Team | Privacy |
| --- | --- |
| CloudLab – IT Department | Private |
| CloudLab – Finance | Private |
| CloudLab – HR | Private |
| CloudLab – Company Wide | Public |
| CloudLab – Management | Private |
| CloudLab – Project Alpha | Private |

The General channel cannot be deleted, so I kept it as the main space and added channels where useful. The IT team has **Help Desk**, **Infrastructure** and **Security** channels.

In the Company Wide team I set the General channel so that only team owners can post. It acts as an announcement board: if everyone could reply, official updates would be buried under other conversation.

## 3. Messaging and meeting policies

**Messaging policy (Global, org-wide default).** I enabled **Read receipts**. I left Giphy on and set the content rating to **Moderate**.

**Meeting policy.**

| Setting | Configuration |
| --- | --- |
| Anonymous users joining meetings | Disabled |
| Cloud recording | Enabled for organisers and co-organisers |
| Meeting transcription | Enabled |
| Lobby bypass | People in my organisation and guests |
| Meeting chat | Enabled during meetings only |

Disabling anonymous join means every attendee signs in with an identity linked to an account, which supports security and gives an audit trail.

## 4. Testing real scenarios

I signed in as different users to check the configuration:

1. As the IT Department Head, I posted an announcement in **CloudLab – Company Wide**.
2. As a Finance employee, I confirmed the announcement was visible but that the user could not reply, because only owners can post.
3. In the Finance team I created a meeting and invited the staff, then joined with a guest account. The guest was placed in the **lobby** until the organiser admitted them.
4. I uploaded a document to the **Files** tab of the IT team and found the same document in the SharePoint site that Teams created for the team.

## What I learned

Creating a team creates a SharePoint site behind it. Files shared in a team are stored in SharePoint, and Teams is the interface on top. That explains why many Teams file-sharing problems are actually SharePoint permission problems.
