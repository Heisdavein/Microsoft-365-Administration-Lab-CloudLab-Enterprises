# 01. Tenant Setup

Before managing users, devices, mail or security, I needed a Microsoft 365 environment to work in. Setting it up properly at the start meant not having to reconfigure it later.

## Enrol in the Microsoft 365 Developer Program

The Developer Program provides a fully functional Microsoft 365 E5 tenant for learning, testing and building solutions, without touching a real organisation.

1. Visit the Microsoft 365 Developer Program site and sign in with a personal Microsoft account.
2. Select **Join Now** and complete the registration form, choosing **IT Administration** as the primary area of interest.
3. Choose the **Instant Sandbox** rather than the configurable sandbox.
4. After a few minutes Microsoft provisions the tenant and assigns a default domain in the form `yourtenant.onmicrosoft.com`. Mine is `cloudlabent.onmicrosoft.com`.
5. Sign in to the Microsoft 365 admin center and confirm the tenant exists.

**Why the Instant Sandbox.** It comes with sample users, Teams conversations, SharePoint content and email, so I could administer something that already looked like a small company instead of an empty tenant.

## Add a custom domain

The `onmicrosoft.com` domain works, but I wanted to learn how organisations connect their own domain, which is one of the first tasks in a real deployment.

1. In the Microsoft 365 admin center go to **Settings, Domains**.
2. Select **Add domain** and enter the domain name.
3. Microsoft generates a **TXT** record to prove ownership. Add it at the domain registrar and wait for DNS to propagate.
4. Return to Microsoft 365 and select **Verify**.
5. Let the wizard guide the remaining records:
    - **MX** for Exchange Online mail delivery
    - **CNAME** records for services such as Autodiscover
    - **SPF** (TXT) to help protect against email spoofing
6. After propagation the domain status changed to **Healthy**.

This gave me practical experience with the DNS records behind mail flow and how Microsoft verifies ownership. The domain name itself is not recorded in this repository.

## Company structure

I created a fictional company so every later task had a business purpose.

| Component | Configuration |
| --- | --- |
| Company name | CloudLab Enterprises |
| Industry | Professional Services |
| Departments | IT, Finance, Human Resources, Sales, Management |
| Total users | 12 |
| Administrative roles | Global Administrator, IT Administrator, Exchange Administrator |
| Licences | Microsoft 365 E5 (25 available, 12 assigned) |
| Tenant domain | `cloudlabent.onmicrosoft.com` |

Planning departments, roles and how each team would use Microsoft 365 meant each later change, from licences to Teams, Exchange, Intune and log reviews, had a realistic reason behind it.
