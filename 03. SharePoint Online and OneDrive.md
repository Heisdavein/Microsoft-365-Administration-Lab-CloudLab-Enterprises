# 03. SharePoint Online and OneDrive

SharePoint is more than file storage: it is a platform for collaboration, document management, team sites and controlled sharing. OneDrive gives each user personal cloud storage. Together they replace the traditional file server. My aim was a structure that mirrors how a real company organises information, with the right people having access to the right files and nothing more.

## 1. How SharePoint is organised

| Component | Purpose |
| --- | --- |
| SharePoint admin center | Manage sites, storage, sharing policies and permissions across the organisation |
| Site collection | Top-level container for one or more sites |
| Team site | Collaboration space for departments and projects |
| Communication site | Company news, announcements and intranet pages |
| Document library | Stores files with version history, permissions and collaboration features |
| OneDrive | Personal cloud storage for each user |

Microsoft encourages organising work around sites rather than folders. Each department can have its own site with separate permissions, which keeps administration cleaner as the organisation grows.

## 2. Department sites

1. SharePoint admin center, **Sites, Active sites**, **Create**.
2. Choose **Team site**.
3. Create one site per department: `CloudLab-IT`, `CloudLab-Finance`, `CloudLab-HR`, `CloudLab-Sales`.
4. Assign the relevant department manager as site owner.
5. Set every site to **Private**, so only approved members can see content.

Private was the first security decision. Public sites make no sense for Finance or HR, and starting private follows the principle of least privilege.

## 3. Libraries and permissions

Instead of using only the default Documents library, I created libraries by type of information.

**Finance**

| Library | Purpose |
| --- | --- |
| Financial Reports | Monthly and annual reports |
| Invoices | Supplier and customer invoices by year |
| Budget Planning | Budget workbooks for management |
| Contracts | Legal agreements and contracts |

**IT:** Technical Documentation, Policies and Procedures, Project Files.

Budget Planning holds sensitive data, so I restricted it:

1. Open **Library settings, Permissions**.
2. Break permission inheritance from the parent site.
3. Remove general Finance staff.
4. Grant **Edit** only to the Finance Manager and CFO accounts.

This is similar to configuring NTFS permissions on a Windows file server, applied to a library instead of a folder. Not every employee in a department should see every document.

## 4. Real-time collaboration and version history

1. Upload a Word document to the Financial Reports library.
2. Open it in Word Online.
3. In another browser, sign in as a different Finance user and open the same document.

Both users edited at once. Changes appeared almost immediately in the other browser, including the other person’s cursor. **Version History** recorded a new version on each save with who changed it, when, and the version number. People can work on one live copy instead of emailing versions around, and earlier versions can be restored after an accidental change.

## 5. OneDrive and sharing policy

OneDrive holds each user’s personal files. The administrator does not manage those files directly but decides how they can be shared and what controls apply.

1. SharePoint admin center, **Policies, Sharing**.
2. Review the default external sharing settings, which range from anonymous links to specific external people.
3. Change the policy so files can be shared only with people inside the organisation, for both OneDrive and SharePoint sites.
4. Review **Access control** options for restricting access from unmanaged devices that are not enrolled in Intune. I reviewed these options; the documentation does not record a change.

Anonymous links can easily become a risk: a confidential file shared with a public link can leave the organisation unnoticed. CloudLab is a professional services company, so sensitive information stays internal unless an administrator approves otherwise.
