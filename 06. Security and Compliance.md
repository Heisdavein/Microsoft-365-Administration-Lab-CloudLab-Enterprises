# 06. Security and Compliance


Most work here used two portals: **Microsoft Purview** for compliance, auditing, data protection and governance, and **Microsoft Defender** for detecting, preventing and responding to threats. I approached each feature with a scenario in mind: a report of leaked data, or a compromised account. Where would I start, and what information would I need?

## 1. Audit logs

The **Unified Audit Log** records activity across Exchange Online, SharePoint Online, OneDrive, Teams and Entra ID: who did what, when, from where and with which application.

1. Sign in to the **Microsoft Purview portal** and open **Audit**.
2. Confirm auditing is already enabled for the tenant.
3. Create a search covering the previous 24 hours.
4. Leave the user field blank to include every user.
5. Select SharePoint, Exchange and Entra ID activities and run the search.

The search returned hundreds of events: sign-ins, email, SharePoint uploads, Teams activity, mailbox access and administrator changes. Each entry shows the user, action, date and time, source IP address, application, workload and extra technical detail. I also exported results to CSV to see what a compliance export looks like.

Typical use: if a manager says a document disappeared from SharePoint, search for the document to see who accessed, edited, deleted or downloaded it and when. This answers the first question in most investigations: “what happened?”

## 2. Data Loss Prevention

A DLP policy scans email, Teams, SharePoint and OneDrive for sensitive information and can warn the user, block the action, alert administrators, or all three.

1. Purview, **Data loss prevention, Create policy**.
2. Choose the **Financial** category and the **UK Financial Data** template.
3. Review the detected types: credit card numbers, UK National Insurance numbers and UK bank account numbers.
4. Apply the policy to Exchange Online, SharePoint Online, Microsoft Teams and OneDrive for Business.

| Scenario | Action |
| --- | --- |
| Sensitive data shared internally | Warn the user |
| Sensitive data sent outside the organisation | Block, notify the user and alert the IT administrator |

I ran the policy in **Simulation mode** first, reviewed what it would have blocked, then enabled enforcement. Warning internally and blocking externally protects company data without constantly interrupting normal work.

## 3. Secure Score

Secure Score measures the tenant’s security posture and recommends prioritised improvements with an explanation and point value for each. My tenant started at approximately **47%**, which reflected recommended features not yet configured rather than an insecure tenant.

Recommendations I worked through:

- Enable Multi-Factor Authentication (MFA) for administrators
- Require MFA for all users
- Block legacy authentication protocols
- Enable Self-Service Password Reset
- Confirm Unified Audit Logging is active
- Configure sign-in risk policies in Microsoft Entra ID

The score rose to approximately **74%**. It gives administrators a structured roadmap, starting with the highest-impact items.

## 4. Defender threat protection

**Safe Attachments.** Attachments can be opened in a secure virtual environment so Microsoft can watch their behaviour. I created a policy for all users with **Dynamic Delivery**: the email arrives immediately with the attachment replaced by a placeholder, and the real file becomes available once scanning confirms it is safe. Users are not left waiting for messages.

**Safe Links.** Links in protected email are rewritten so that every click is checked against Microsoft’s threat intelligence, even days after delivery. This covers links that become malicious later. I enabled real-time URL scanning, protection for email, protection for Microsoft Teams, and warning pages before users visit dangerous sites.

**Anti-phishing.** I reviewed **Mailbox Intelligence**, which learns each user’s normal communication patterns. A message claiming to be from the CEO but from an address the recipient has never dealt with can be flagged, so detection does not depend only on known-bad senders. The protected-user setup is in Exchange Online.

## 5. Sensitivity labels

A sensitivity label classifies documents and can apply protection automatically. In **Purview, Information protection** I reviewed the default labels (Public, General, Confidential, Highly Confidential) and created **CloudLab Confidential Finance**:

- Applies to files, emails and meetings
- Encrypts documents automatically
- Only Finance department users can open protected files
- Adds the header and footer “CloudLab Confidential – Finance Use Only”
- Applies automatically when UK bank account information is detected

After publishing it, the label appeared in Word’s ribbon for a Finance user. I applied it to a sample financial document: the confidentiality header appeared, and opening the file with an account outside Finance was denied. The protection stays with the document if it is copied, emailed or uploaded elsewhere.

## Layered defence

| Control | Role |
| --- | --- |
| Audit logs | Visibility into what happened |
| DLP | Prevents sensitive data leaving |
| Defender | Blocks malicious email, links and attachments |
| Secure Score | Shows weaknesses and priorities |
| Sensitivity labels | Keeps confidential data protected wherever it travels |
